# OpenFlix local API

All API routes are OpenFlix-owned. Browser requests are same-origin and credentials remain in an HttpOnly cookie.

| Method/path                | Behavior                                                                                                                                                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /health`              | Public readiness: 200 `{"status":"healthy","database":"ok"}`; 503 with `unhealthy`/`unavailable` if the DB probe fails. No connector/peer claims.                                                                                                                                                            |
| `POST /api/v1/auth/login`  | JSON `{ "username": "…", "password": "…" }`, exact configured Origin required. 200 `{ "user": { "id", "username", "displayName", "role" } }` and a session cookie. 401 generic invalid credentials; 400 malformed input; 403 wrong/missing origin; 413 oversized; 429 rate limit; 503 password workers busy. |
| `GET /api/v1/me`           | 200 safe user projection for a valid unexpired session, otherwise 401.                                                                                                                                                                                                                                       |
| `POST /api/v1/auth/logout` | Exact configured Origin required. Revokes presented session, expires cookie, returns 204. Idempotent even without a session.                                                                                                                                                                                 |

The M1 routes above and M2/M3/M4 routes below are implemented. Other routes return 404. Errors are `{ "error": "safe message" }`; raw validation/database errors are not returned. Request IDs are generated by the server and returned in `X-Request-Id`. Responses are not cacheable.

## Milestone 2 administrator media servers

All routes below require an authenticated OpenFlix **admin**. Mutations also require the exact configured `Origin`, with existing body/time/rate limits. Ordinary users receive 403; anonymous requests receive 401. Successful projections contain normalized identity/state/library metadata only, never a password, token, encrypted envelope or key.

| Method/path                        | Behavior                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/connectors`           | `{connectors, credentialStorageConfigured}`; saved metadata, no network probe                                                              |
| `POST /api/v1/connectors`          | Body `{name, baseUrl, username, password}`; authenticate/test/list accessible views, atomically save encrypted record; 201 `{connector}`   |
| `POST /api/v1/connectors/:id/test` | Reconnect/test saved credential and refresh identity/libraries; 200 `{connector}`                                                          |
| `DELETE /api/v1/connectors/:id`    | Attempt session revocation, remove local record and cascade its catalog/staging; `{removed:true, revocation:"confirmed" \| "unconfirmed"}` |

Connector errors return fixed `{error, code}` values: invalid configuration (400), not found (404), credential unavailable/busy (503), or sanitized upstream failures (502). Codes include `unauthorized`, `unavailable`, `timeout`, `unsupported`, `unsafe_redirect`, `invalid_response`, and `identity_mismatch`. These describe Jellyfin failures, not an OpenFlix login challenge. Failed tests mark state `error` and clear cached library metadata; restart marks saved connections `unverified` until explicitly tested.

## Milestone 3 normalized catalog

All routes require a valid OpenFlix session. All authenticated users may browse the same published catalog; no Jellyfin user mapping is implied. Sync mutations additionally require administrator role and exact Origin. Responses never contain upstream credentials, ciphertext, raw DTOs or filesystem paths. Client types are in `packages/protocol` and `packages/shared`.

| Method/path                               | Behavior                                                                                                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/catalog/libraries`           | `{libraries}` with OpenFlix/source IDs, source display name, upstream library ID, name, normalized type, nullable upstream type and last successful sync time                                                     |
| `GET /api/v1/catalog/libraries/:id/items` | `{items,total,offset,limit}`; optional `offset` (0–1000000), `limit` (1–100, default 50), normalized `type`, source-scoped OpenFlix `parentId`; stable sort title then item ID                                    |
| `GET /api/v1/catalog/items/:id`           | `{item}`; normalized metadata, source identity, memberships and source-scoped relationships; missing/unresolved item returns 404                                                                                  |
| `GET /api/v1/catalog/sync/:connectorId`   | Current/latest state (`never`, `syncing`, `successful`, `failed`), scope, timestamps and fixed sanitized error code; no network request                                                                           |
| `POST /api/v1/catalog/sync/:connectorId`  | Admin-only body `{}` for full source scan or `{libraryId}` for one existing catalog library; returns 202 with operation state; poll status; 503 when another connector mutation/sync is active or key unavailable |

Browse is a database read, never an upstream request. Sync failure preserves all previous published items/memberships and timestamps. Full successful reconciliation can remove disappeared views/items; targeted sync only replaces that library's memberships. Other errors use existing sanitized 400/401/403/404/429/503 behavior. See [catalog guarantees](catalog.md) for pagination and offset-snapshot limitations. M3 adds no search/artwork endpoints; playback is described below.

## Milestone 4 playback

See [direct playback routes](playback.md#api) and [current HLS scope](status.md#playback-scope). The session profile also accepts `hls-h264-aac`; plans distinguish direct/remux/transcode. The HLS entry uses the session `streamPath`; rewritten HLS resources use authenticated GET/HEAD `/api/v1/playback/sessions/:id/resources/:resource` routes. Playback is admin-only even though catalog metadata remains shared. Only same-origin, authenticated media routes are returned. No schema migration or persistent watch history is added.
