# Optimus Milestone 4 integration audit

Builder status can only be READY FOR INTEGRATION AUDIT. Deterministic protocol fixtures and decoded synthetic media are not independent Jellyfin 10.11.11 playback acceptance.

1. Verify ZIP checksum, manifest source commit, source hashes and changed-file inventory; reproduce builder checks. Preserve M1/M2/M3 audit tags and original archives.
2. Obtain explicit operator approval for Jellyfin playback reporting and use an authorized test identity. Start/progress/stop can change watch progress/history. Do not change household configuration, libraries, media, plugins, playlists or account permissions. If approval or a suitable existing identity is unavailable, report that test as not performed.
3. Deploy privately behind trusted HTTPS with a new private data volume and operator-provided master key. Also test a stopped backup of an M3 volume: accounts, encrypted connection, catalog and migration ledger must survive; re-enter no Jellyfin password.
4. On real Jellyfin 10.11.11 inspect available source codecs and test a supported MP4 H.264/AAC movie, supported episode, MP3 or WAV audio. Record actual browser/OS and source formats, decoding, audible output where feasible, duration, progress, pause/resume, seek/range and fullscreen. Do not infer universal codec support. MKV/HEVC/surround/HDR and other excluded formats should return a clear unsupported error. HLS/transcoding is deliberately absent and must not be claimed as passed.
5. Test desktop Chromium and Safari; if safely available test a real iPhone over trusted HTTPS (playsInline, native controls, seek, background/navigation behavior). A mobile-sized desktop viewport is not iOS evidence.
6. Verify missing login, ordinary-user denial despite visible catalog, cross-user/different-login grant denial, forged item/source/URL/query denial, logout/expiry, connector removal and interrupted transfers. Only admins may play; no ordinary-user source mapping is implemented.
7. Confirm permanent token, encrypted envelope, master key, upstream URLs and filesystem paths are absent from playback JSON, browser request URLs and logs. Browser media requests must remain same-origin OpenFlix. Check redirect rejection and normal TLS verification without changing live server configuration.
8. Observe authorized Jellyfin start/progress/stop behavior with real positions, paused/seek state and cleanup. Confirm no new Jellyfin authentication is created for each playback request. Inspect unconfirmed cleanup behavior during a safe simulated network interruption, not by disrupting household service.
9. Restart/recreate only the isolated OpenFlix deployment. Old grants must fail cleanly, new grants must work with persisted credentials; catalog/sessions/storage modes remain intact. Check cancellation, bounded concurrent streams and large-file memory behavior.
10. Use an existing restricted Jellyfin account if safely available; verify accessible items can play and inaccessible ones cannot be selected through forged requests. Do not create users or alter real permissions to satisfy testing.

Carry forward M3 limitations: imported metadata is shared among authenticated OpenFlix users; source offset pagination is not a transactional snapshot; mixed music containing playlists is legitimate. M4 adds no playback permission for ordinary users, adaptive transcoding, subtitles/track selection, watch-history persistence, federation or Milestone 5 work.
