# Optimus: independent Milestone 2 integration audit

Builder checks use local fixtures, not the household OptiPlex. Do not accept production compatibility solely from those results. Milestone 2 remains **READY FOR INTEGRATION AUDIT** only after the documented builder suite passes; it is not an independently audited release.

1. Verify the detached ZIP checksum, manifest source inventory and exact Git commit. Preserve the audited M1 R2 tag. Run `pnpm install --frozen-lockfile`, `pnpm check`, both dependency audits and `pnpm verify:docker` from a fresh copy with safe TMPDIR and no production data mounted.
2. Read the actual Jellyfin version using its public system information and inspect that version's official OpenAPI. Compare with [recorded SDK/API baseline](jellyfin-preparation.md). Report unsupported versions; do not upgrade/configure the live server merely to satisfy a test.
3. Use an existing suitable Jellyfin account with known limited library access, with household operator approval for authentication/session creation and revocation. Do not alter server configuration, libraries/media or plugins. Use a separate OpenFlix database and a private, separately provisioned random master key.
4. Provision an OpenFlix administrator through the existing local CLI. Add the actual final HTTP(S) base URL, including any reverse-proxy prefix. Verify TLS trust with normal certificate validation. Check useful rejection for redirects and invalid credentials without weakening security.
5. Confirm displayed server identity/version and that enumerated libraries match that Jellyfin user's accessible views, including restricted/hidden/external-library behavior. Ensure an ordinary OpenFlix user cannot call any connector route. Confirm no catalog, artwork or playback requests occur.
6. Inspect the isolated OpenFlix SQLite records and primary/WAL/SHM files: ciphertext envelope present, no plaintext Jellyfin password/token/master key. Confirm directory ownership/mode 0700 and database/sidecars 0600, plus preserved migrations/accounts/sessions.
7. Restart OpenFlix and recreate its container without deleting its volume. Confirm state becomes unverified; reconnect refreshes the correct identity/libraries using the saved token, without re-entering the password or creating another Jellyfin authentication session.
8. On copies of the test database only, tamper ciphertext/tag or change the master key; verify fail-closed startup before network requests and no disclosure in logs. Restore the original unmodified copy/key afterward.
9. Disconnect/remove: confirm only this connector's Jellyfin session is invalidated according to the actual server API, the local encrypted record is gone, and unrelated Jellyfin sessions remain valid. Repeat with the server unreachable and verify explicit unconfirmed-revocation messaging; arrange later manual revocation if needed.
10. Inspect application/reverse-proxy logs, HTTP responses, browser storage and error paths for passwords/tokens/keys. Do not paste real credentials or secret-bearing captures into an audit report. Verify the real admin UI over trusted HTTPS, reload, reconnect and removal.

Record exact server version, proxy/base-path topology, operating system/architecture, OpenFlix commit, commands and results. Any mismatch in identity, token lifetime/revocation, library visibility or API contract is a finding to remediate before independently accepting M2. Do not begin catalog synchronization (M3) during this audit.
